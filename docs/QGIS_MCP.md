# Интерактивная работа в QGIS (qgis-mcp)

Для проверки глазами на Mac: агент открывает проект в настоящем QGIS, включает слои, меняет масштаб, смотрит снимок экрана. Это инструмент проверки, не выпуска. Выпуск собирает только `cm-carto render` из описания карты (правило 8 паспорта).

## Что подключается

Два MCP-сервера в `.mcp.json` в корне репозитория:

| Сервер | Что это | Как запускается |
|---|---|---|
| `cm-carto` | функции картографа: `doctor`, `ingest`, `fetch`, `render`, `isochrone`, `measure`, `buffer`, `count`, `qgis_project` | `scripts/run.sh cm-carto-mcp`, QGIS без окна внутри процесса |
| `qgis` | [`nkarasiak/qgis-mcp`](https://github.com/nkarasiak/qgis-mcp), 125 инструментов над запущенным окном QGIS | `uvx` из архива репозитория |

`qgis-mcp` состоит из двух частей: плагин внутри QGIS (TCP-сокет на `localhost:9876`, команды выполняются в цикле событий QGIS) и MCP-сервер снаружи (FastMCP), который говорит с плагином по сокету. Агент → сервер `qgis` → сокет → плагин → PyQGIS окна. С сервером `cm-carto` общего процесса и общего состояния нет: он собирает файлы, `qgis` смотрит их в окне.

## Подключение на Mac

1. **Окружение картографа** — по `docs/ПЕРЕНОС.md` (micromamba, QGIS 3.44 из `environment.yml`). Окно QGIS для интерактивной работы — тот же QGIS 3.44 из этого окружения (`micromamba run -n cm-carto qgis`) или обычное приложение QGIS 3.44 LTR.
2. **uv** (для `uvx`): `brew install uv`.
3. **Плагин** в окне QGIS: `Плагины → Управление и установка плагинов →` найти **QGIS MCP** → установить, перезапустить QGIS, в панели QGIS MCP нажать **Start Server**. Плагин слушает только `localhost`.
4. **Токен** (общая машина): значение `QGIS_MCP_TOKEN` задать в среде, где запущен QGIS, и тем же значением в `env` сервера `qgis` в `.mcp.json`; без токена любой процесс на машине управляет QGIS, включая `execute_code` (произвольный PyQGIS).
5. **Переменные для сервера `cm-carto`** перед запуском Claude Code в корне репозитория (значения по умолчанию в `.mcp.json` — облачные пути `/opt/mm`):
   ```bash
   export MM=$(command -v micromamba)
   export MAMBA_ROOT_PREFIX=$HOME/micromamba
   export CM_CARTO_ENV=$HOME/micromamba/envs/cm-carto
   export CM_CARTO_PROJECT=examples/taganrog        # папка проекта; относительные пути инструментов — от нее
   claude
   ```
6. Проверка: инструмент `doctor` сервера `cm-carto` отвечает «окружение годно»; инструмент `ping` сервера `qgis` возвращает `{"pong": true}`; `diagnose` сверяет версию плагина и сервера (после обновления одного из них — перезапустить плагин: Stop / Start).

Другие клиенты (Codex, Gemini CLI, Cursor, VS Code и т. д.) — тот же `command`/`args` в их файле настроек; список — в README `qgis-mcp`.

## Как смотреть карту глазами

1. `qgis_project` (сервер `cm-carto`) с описанием карты: `{"spec": "maps/k1-analysis.yaml"}` → `maps/images/k1-analysis.qgz`. Это те же слои, отборы (`where`, `within`) и стили верстки (`design/qgis/<роль>.qml`), что у `render`, но без обрезки по охвату; компоновка места `map_<место>.qpt` — с охватом карты; путь к геопакету в проекте относительный.
2. `load_project` (сервер `qgis`) с путем к `.qgz`; затем `get_layers`, `set_layer_visibility`, `set_canvas_scale`, `get_canvas_screenshot` — смотреть.
3. Нашли расхождение — правят описание карты, правила или данные и пересобирают `render`; проект `.qgz` пересоздается `qgis_project`. Сохраненные в `.qgz` ручные правки в выпуск не попадают и перезаписываются.

## Правила

- **Выпускной геопакет — только на чтение (Э-005).** Слои проекта `qgis_project` помечены «только чтение». Не вызывать на слоях геопакета проекта `start_editing`, `add_features`, `update_features`, `delete_features`, `field_calculator`, `add_field`, `delete_field`, `rename_field`, `import_layer_to_connection`, `execute_connection_sql`, `execute_processing` с записью в него. Даже открытие на запись переводит GPKG в журнал WAL: файл меняется, хэш кеша не совпадает, повтор карты ломается.
- **Опыты — на копии.** Нужны правки или проба алгоритма — скопировать `project.gpkg` в `_build/` и работать с копией; результат опыта выпуском не становится.
- **Ручные правки в выпуск не идут (правило 8).** Что-то стоит исправить в карте — это правка описания (`schema/map.schema.json`), правил раскладки (`rules/`), токенов верстки или данных, затем `render`. Компоновку и стили, сохраненные из QGIS, картограф не читает.
- **Источники и статусы не меняются в QGIS.** Повысить статус геометрии может только документ (правило 3), поэтому в QGIS атрибуты `status`, `source_*` не правятся.
- `execute_code` и `batch_commands` `qgis-mcp` — произвольный код в QGIS; запускать только по прямой просьбе и не на геопакете проекта.
