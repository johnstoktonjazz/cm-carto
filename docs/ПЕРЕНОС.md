# Перенос картографа на Mac

Что нужно: тот же код, что в облаке, без правок. Проект задается анкетой `project.yaml`; смена проекта — другая анкета и другие данные, код не трогается (проверка скриптом: `tests/test_no_project_words.py`).

## 1. Что ставится

| Что | Версия | Зачем |
|---|---|---|
| micromamba (или conda) | любая свежая | окружение из `environment.yml` |
| QGIS | 3.44 LTR, ставится в окружение (`qgis=3.44` с conda-forge) | PyQGIS без окна для рендера и `doctor`; отдельное приложение QGIS нужно только для `qgis-mcp` |
| шрифты Open Sans | файлы из `cm-design/input/fonts/OpenSans-*.ttf` | подписи карт; `doctor` проверяет, что шрифты из токенов видны QGIS |
| uv | любая свежая | `uvx` для `qgis-mcp` |
| git | | репозитории `cm-carto` (с подмодулем `cm-contracts`) и `cm-design` рядом |

## 2. Установка

```bash
brew install micromamba uv                      # или установщик micromamba с conda-forge
mkdir -p ~/work && cd ~/work
git clone --recurse-submodules <адрес cm-carto> cm-carto
git clone <адрес cm-design> cm-design           # рядом; иначе CM_DESIGN=путь
cd cm-carto
export MAMBA_ROOT_PREFIX=$HOME/micromamba
micromamba create -y -p $HOME/micromamba/envs/cm-carto -f environment.yml
micromamba run -p $HOME/micromamba/envs/cm-carto pip install -e .      # команды cm-carto и cm-carto-mcp
mkdir -p ~/Library/Fonts && cp ../cm-design/input/fonts/OpenSans-*.ttf ~/Library/Fonts/
export MM=$(command -v micromamba) CM_CARTO_ENV=$HOME/micromamba/envs/cm-carto
scripts/run.sh cm-carto doctor                  # «окружение годно»
scripts/run.sh python -m pytest                 # необязательно: тесты на правила и на случившиеся ошибки
```

Замечания:

- `scripts/setup_env.sh` рассчитан на Linux (скачивает `micromamba-linux-64`, кладет шрифты в `~/.local/share/fonts`, вызывает `fc-cache`); на Mac его не запускать, шаги выше — его аналог.
- Если `cm-design` лежит не рядом, а `cm-contracts` не подмодулем: `export CM_DESIGN=/путь/cm-design CM_CONTRACTS=/путь/cm-contracts`. Других путей в коде нет: единственные зашитые значения — умолчания `/opt/mm/...` в `scripts/run.sh` и `setup_env.sh`, переопределяются `MM`, `MAMBA_ROOT_PREFIX`, `CM_CARTO_ENV`.
- `scripts/run.sh` ставит `QT_HASH_SEED=0` (одинаковый порядок атрибутов SVG у всех процессов) и `QT_QPA_PLATFORM=offscreen` берется кодом; запуск мимо `run.sh` — те же переменные вручную. MCP-сервер ставит `QT_HASH_SEED=0` сам.
- Повторяемость карты байт в байт держится на версии QGIS, GDAL и шрифтах: сравнивать карты, собранные на Mac и в облаке, имеет смысл при одинаковых версиях (`doctor` печатает версию QGIS). На проверке копии в другой папке облака PNG и `overlay.json` образца совпали с исходными.

## 3. Проект: `project.yaml`

Все проектное — в анкете и данных проекта. Пример — `examples/taganrog/project.yaml`.

```yaml
name: <имя проекта>
crs:
  name: <как подписывать: EPSG-код или МСК с зоной>
  definition: "<EPSG:NNNNN, строка PROJ или WKT>"   # для МСК — параметры строкой PROJ или WKT
extent_wgs84: [xmin, ymin, xmax, ymax]               # охват выгрузок внешних источников, градусы
language: ru
geo: <папка геоданных от папки анкеты>               # parts/*.gpkg и project.gpkg
inputs: <папка образцов и кеша от папки анкеты>      # кеш внешних источников с датой и лицензией
fetch:
  overture_release: <выпуск Overture Maps>
```

Рядом с анкетой: `registry/norms.yaml` (записи NORM для буферов), описания карт `maps/*.yaml` (`project: ../project.yaml`). Порядок для нового проекта:

1. `cm-carto ingest project.yaml <папка с DXF, КПТ, SHP, GPKG>` (у DXF, SHP, GPKG рядом `<файл>.source.yaml`: правила раскладки из `rules/`, подпись, дата, лицензия);
2. `cm-carto fetch project.yaml osm` или `overture`, реестры (`okn`, `dtp`, `bus_gov`, `hotels`, `rosstat`) и `reconcile`;
3. части `geo/parts/*.gpkg` сливаются в `project.gpkg` (`gpkg.merge`, как в `scripts/build_k1.sh`);
4. `isochrone`, `buffer`, `measure`, `count`;
5. `render` по описаниям карт (`MAPS_USAGE.md`).

Ни одной правки кода: другой проект — другая анкета, другие правила раскладки в `rules/` (если у источника иная раскладка слоев) и записи NORM; значения вроде названий, номеров документов и координат в коде запрещены.

Что не переносится вместе с репозиторием (в `.gitignore`): `geo/project.gpkg`, `geo/parts/fetch-*.gpkg`, `geo/parts/analysis-*.gpkg`, `input/**/cache/`, `_build/`. На новой машине их воспроизводят `fetch` (из закрепленного выпуска и кеша) и слияние частей; готовый `project.gpkg` полигона копируют файлом.

## 4. Что проверить на Mac

В этом порядке; облако этого проверить не могло.

1. `doctor`: QGIS 3.44, шрифты видны, пробная карта собрана и повтор дал тот же файл.
2. **OSM напрямую:** `cm-carto fetch project.yaml osm` без `--file` (Overpass). В облаке проверен только разбор выгрузок и синтетика; нужны: ответ сервера на охват проекта, лимиты, лицензия ODbL и дата выгрузки в слоях.
3. **Реестры:** `fetch ... okn|dtp|bus_gov|hotels|rosstat` с настоящими выгрузками (`--file`, `--date`) — в облаке разбор проверен только на синтетических файлах; сверить названия столбцов, кодировку, разделитель с `ПОДКЛЮЧЕНИЯ.md`.
4. Образец полигона: `ingest` образцов, слияние, `render` одной карты из `examples/taganrog/maps/`; образцы К1 целиком — `scripts/build_k1.sh`.
5. **MCP:** `cm-carto-mcp` через `.mcp.json` (инструменты `doctor`, `render`, `qgis_project`), затем `qgis-mcp` по `docs/QGIS_MCP.md`: `ping`, `load_project` на `.qgz` из `qgis_project`, снимок холста.
6. Первая настоящая сборка: проект с реальной анкетой, `ingest` DXF и КПТ проекта, отчет импорта (что не распознано, что подтвердить), затем карты.
