## К-001. Город-полигон — Таганрог

11.10.2026. Средний город (около 240 тыс. жителей), как у проектов CM: морской берег, железная дорога вдоль берега, исторический центр с регулярной сеткой кварталов и плотным реестром ОКН, порт, промзоны. Покрытие открытыми данными проверено: в Overture Maps 2026-09-23.0 на охват города 9 007 сегментов улиц по классам, 217 остановок, 1 235 объектов places, инфраструктура и вода. Система координат полигона — UTM 37N (EPSG:32637); МСК субъекта не берется, потому что ее параметры не опубликованы официально, а выдуманные параметры выдавали бы себя за настоящие. Путь «МСК строкой PROJ или WKT» проверяется тестом на синтетической поперечной Меркатора. Анкета — `examples/taganrog/project.yaml`.

Запасной путь `geopandas + matplotlib` не нужен. Образец верстки (`examples/graphics/maps/01-map-analysis.yaml`) в QGIS 3.44 дает PNG, совпадающий байт в байт с их рендером в QGIS 3.34.

## К-003. Внешние данные из облака — через Overture Maps

11.10.2026. Сеть облака закрыта для Overpass API, Geofabrik, ФГИС ТП, НСПД, bus.gov.ru, opendata.mkrf.ru, openrouteservice (прокси отвечает 403). Открыты GitHub и S3 Overture Maps. ## К-005. Контракт geopackage 1.1.0

11.10.2026. Пункты confirm черновика 1.0.0:
1. Перечень слоев: 27 слоев, геометрия закреплена за слоем (площади `MultiPolygon`, линии `MultiLineString`, точки `Point`): в GPKG у таблицы одна геометрия, а DXF и ЕГРН дают составные контуры. Убран `basemap_extent`: охват — свойство карты, не данных. Атрибуты — закрытый перечень по слою.
2. `object_id` — `слой:ключ`, ключ из источника (кадастровый номер, номер элемента OSM, номер реестра, номер из чертежа), иначе SHA-256 геометрии с округлением до 1 см. Устойчив между сборками при тех же входах; изменения против прошлой сборки — в отчете `ingest`.
3. `fact_ids` и `attrs` в GPKG — обычные столбцы; списки — JSON-текстом. Связанные таблицы не нужны: связь объект → записи реестра односторонняя, читает ее база по `object_id`.
Еще: `fact_ids` обязателен (пустой список допустим) — база отличает «нет записей» от «забыли»; `source_license` обязателен у `reference` — проверка печати по лицензии скриптом; времени сборки в файле нет (`input_hash`), даты `gpkg_contents` постоянные — повторная сборка дает тот же файл (тест `tests/test_gpkg.py`).
Слои геопакета — данные, слои `map.yaml` верстки — роли на карте; связь — в описании карты (роль ← слой и отбор). Изменение — ветка `claude/great-wright-7nnzst` в `cm-contracts`; ждет подтверждения базы и слияния Романом.

## К-007. Образцы DXF и КПТ — синтетические

11.10.2026. ФГИС ТП и НСПД из облака закрыты; реальные КПТ содержат данные правообладателей. Образцы делаются скриптом: DXF проекта планировки с типовыми слоями (граница, красные линии, кварталы, зоны размещения, подписи номеров, мусорные слои, незамкнутые контуры) и КПТ в XML-структуре выписки Росреестра (участки, ЗОУИТ, территориальные зоны) с вымышленными кадастровыми номерами вида `00:00:…`. Геометрия привязана к улицам полигона, чтобы карты были осмысленными; статус — `official` и `cadastral` как у настоящих, источник подписан «синтетический образец».

## К-008. Геопакет проекта собирается из частей

11.10.2026. Каждая команда (`ingest` по каждому входу, `fetch` по каждому источнику, `analysis`) пишет свою часть `geo/parts/<имя>.gpkg`, каждая проходит контракт. Геопакет проекта `geo/project.gpkg` — слияние частей (`cm_carto.gpkg.merge`): слои одного имени складываются, повтор `object_id` — ошибка. Так исполнители не пишут в один файл (правило полной загрузки, п. 5), а пересборка одного входа не трогает остальные.
