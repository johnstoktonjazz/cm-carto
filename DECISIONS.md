## К-005. Контракт geopackage 1.1.0

11.10.2026. Пункты confirm черновика 1.0.0:
1. Перечень слоев: 27 слоев, геометрия закреплена за слоем (площади `MultiPolygon`, линии `MultiLineString`, точки `Point`): в GPKG у таблицы одна геометрия, а DXF и ЕГРН дают составные контуры. Убран `basemap_extent`: охват — свойство карты, не данных. Атрибуты — закрытый перечень по слою.
2. `object_id` — `слой:ключ`, ключ из источника (кадастровый номер, номер элемента OSM, номер реестра, номер из чертежа), иначе SHA-256 геометрии с округлением до 1 см. Устойчив между сборками при тех же входах; изменения против прошлой сборки — в отчете `ingest`.
3. `fact_ids` и `attrs` в GPKG — обычные столбцы; списки — JSON-текстом. Связанные таблицы не нужны: связь объект → записи реестра односторонняя, читает ее база по `object_id`.
Еще: `fact_ids` обязателен (пустой список допустим) — база отличает «нет записей» от «забыли»; `source_license` обязателен у `reference` — проверка печати по лицензии скриптом; времени сборки в файле нет (`input_hash`), даты `gpkg_contents` постоянные — повторная сборка дает тот же файл (тест `tests/test_gpkg.py`).
Слои геопакета — данные, слои `map.yaml` верстки — роли на карте; связь — в описании карты (роль ← слой и отбор). Изменение — ветка `claude/great-wright-7nnzst` в `cm-contracts`; ждет подтверждения базы и слияния Романом.

## К-008. Геопакет проекта собирается из частей

11.10.2026. Каждая команда (`ingest` по каждому входу, `fetch` по каждому источнику, `analysis`) пишет свою часть `geo/parts/<имя>.gpkg`, каждая проходит контракт. Геопакет проекта `geo/project.gpkg` — слияние частей (`cm_carto.gpkg.merge`): слои одного имени складываются, повтор `object_id` — ошибка. Так исполнители не пишут в один файл (правило полной загрузки, п. 5), а пересборка одного входа не трогает остальные.

## К-009. Описание карты

11.10.2026. `schema/map.schema.json`: место, анкета проекта, охват (`extent` или `center` + `scale`), север, легенда, роли `map.yaml` ← слой геопакета и отбор `where` (subset string QGIS), заголовок, `fact_ids`, выход. Проверка один раз при загрузке: по схеме и по стандарту верстки (роль есть, слой есть, геометрия подходит роли, система координат геопакета — анкеты). Описания верстки переносятся заменой `data:` на `project:` и `layers.<роль>.data` на `layer` + `where`; `provenance:` не нужен — собирается из данных.

## К-010. Карта рисует только охват

11.10.2026. Объекты роли ограничиваются охватом карты (`fid IN`), поэтому подписи «до пяти объектов», легенда (только встреченные виды зон) и `provenance` считают то, что нарисовано (`MAPS.md`, раздел 1). Роль без объектов в охвате не рисуется и в легенду не идет. Север вверху всегда; стрелка — только если в охвате нет подложки.

## К-011. Сводные поля provenance

11.10.2026. `source` — уникальные пары «подпись, лицензия» объектов в охвате по слоям в порядке стандарта; `date` — самая поздняя дата данных на карте, даты слоев — в `layers[]`; статус слоя — самый слабый у его объектов (`official < cadastral < concept < digitized < reference`); статус карты — самый слабый среди слоев легенды, кроме `reference` (его нет в `image: status` — вопрос верстке). Карта, у легенды которой все слои `reference`, до ответа не собирается: ошибка с текстом про контракт. Файл проверяется по схеме `image` при каждой сборке.

## К-012. Воспроизводимость рендера

11.10.2026. `QT_HASH_SEED=0` (Э-006), геопакет открывается только на чтение (Э-005), метаданные экспорта выключены. Кеш по хэшу описания, анкеты, геопакета, токенов, стилей верстки, схемы `image`, кода рендера и версии QGIS — `_build/cache/`; повтор не запускает QGIS. Тест: две сборки в двух процессах — PNG и SVG байт в байт.

11.10.2026. Источники, запрещенные к печати (Яндекс, 2ГИС, Google), — `cm_carto/render/print.yaml`; проверка по `source_license` и `source_label` объектов на карте; нарушение — ошибка рендера.

## К-014. Части из внешних источников не хранятся в git

11.10.2026. `fetch-overture.gpkg` полигона — 37 МБ. Она полностью воспроизводится `cm-carto fetch` из закрепленного выпуска Overture (в анкете), поэтому в git не идет (`.gitignore`). Документные части (`ingest-*`) малы и хранятся: их входы — образцы в `input/`. Геопакет проекта `geo/project.gpkg` — слияние частей, тоже не хранится.

## К-015. Паспорт источника и правила ingest

11.10.2026. У DXF, SHP и GPKG рядом лежит `<файл>.source.yaml`: имя правил, подпись, дата, у чужих данных — лицензия. В самих файлах этого нет, а в правилах проектных значений быть не может. У КПТ подпись и дата — из реквизитов выписки. Статус слоя задают правила, а не паспорт (повышает статус только документ). Правила (`rules/*.yaml`, схема `schema/rules.schema.json`) сверяются со схемой и контрактом один раз при загрузке.

## К-016. Охват как проверка системы координат

11.10.2026. В DXF и КПТ нет надежной системы координат: ingest принимает проектную и падает, если объекты вне охвата проекта (с 12.10 — `extent` в СК проекта, К-044). Так ловятся перепутанные оси Росреестра (x — север), местная система и единицы не в метрах. В КПТ `coord_system` сверяется с `crs.name` проекта (пока точным совпадением строки — до живого образца).

## К-017. Ключи object_id из чертежа

11.10.2026. Номер из текста внутри контура — ключ (кириллица латиницей: `8а` → `blocks:8a`; `num` хранит исходный текст). Без номера — хэш геометрии по контракту. Красные линии — ключ по геометрии цепочки (линии, соединенные концами в допуске 0,5 м). Допуск замыкания контуров — 0,5 м, параметр правил.

## К-018. Карта = растр подложки + слои overlay (решение Романа)

11.10.2026. Решение Романа: все, что на карте, кроме подложки, редактируется в PowerPoint. Рендер дает из одного описания два выхода: `<карта>.png` — только подложка (кварталы, застройка, вода, зелень, улицы, ж/д и их подписи) в размер места, 300 dpi, с `provenance.json` по контракту `image`; `<карта>.overlay.json` — все остальное в миллиметрах места (начало — левый верхний угол, ось y вниз, как в PowerPoint): контуры границ, зон, буферов, изохрон с упрощением 0,1 мм; точки с типом знака; подписи с точкой привязки; строки легенды с ролью образца; масштабная линейка; север. Стиль в overlay не копируется: у каждого элемента роль `map.yaml`, цвета и толщины верстка берет из токенов. До контракта `overlay` (пришлет Роман в `cm-contracts`) — черновая схема картографа `schema/overlay.draft.schema.json`; после — подгонка под контракт. Сборка листов с overlay — за версткой (`cm-deck`); до этого образцы К1 проверяются превью (overlay поверх подложки, только для проверки). Отменяет цельный PNG карты из К-009…К-011 в части выхода; описание карты, отбор по охвату, правила provenance и воспроизводимость остаются.

## К-019. fetch: правила раскладки внешних источников

11.10.2026. По отчету `fetch-dev` (`reports/agents/fetch-dev.md`):
- Море — полигоны Overture `sea`, `bay`, `ocean` (`water_class = sea`), приведенные к непересекающимся; вычитание суши не нужно (совпадает до 1e-16). Для прямого OSM — из `natural=coastline`.
- Кварталы подложки — суша охвата минус полосы улиц по классу (14 м express и main, 11 district, 8 local, 5 pedestrian от оси), без service, path и подземных участков; отсев мелких, огромных и обрезанных охватом. Числа — `rules/fetch.yaml`.
- `object_id` улиц — по элементу OSM: сегмент Overture режется обратно по элементам (`sources[].between`), подземный участок — `osm-w123-t`; без OSM — `ovt-<GERS>`.
- Классы: `track`, `unknown` → `service`; `crosswalk`, `sidewalk` → `path`; `*_link` наследуют класс; класс вне таблицы — ошибка.
- Подпись и лицензия — по поставщику первой записи `sources` (OSM, Microsoft ML Buildings — ODbL 1.0; Places — CDLA-Permissive-2.0).
- Places: уверенность от 0,5, без закрытых; точка внутри объекта `land_use` той же группы — дубль, остается объект OSM.
- Сверка с реестром: тот же `poi_type`, до 150 м, общие различающие слова названия от 0,6, цифры совпадают; сведенная запись — ключ реестра, геометрия OSM, `confirmed_by` с обоими; объект OSM группы, покрытой реестром, без пары — «не подтверждено реестром» в подписи.
- Реестры кладутся в кеш файлом (`--file`, `--date`): порталы закрыты из облака; имена столбцов — `rules/registries.yaml`. НСПД не подключается (нет открытого интерфейса).
- Целые атрибуты с пропусками приводятся к целым при записи геопакета (`gpkg.write`, по типу схемы контракта).

## К-020. Граф улиц — по общим вершинам

## К-024. Модели и уровень усилий исполнителей (указание Романа)

11.10.2026. Раздел 10 паспорта «Роли и модели» применяется буквально: оркестратор, `verifier` и роли с пометкой «сильная» — Opus; остальные исполнители (окружение, тесты, выгрузки, конвертеры, линтер, ingest, fetch, analysis, mcp) — Sonnet. Уровень усилий исполнителей — обычный (`effort: medium`); повышенный (`high`) — только оркестратору на планировании и `verifier` на контрольных точках. Задача исполнителя проверяется тестом и линтером, а не его собственной тщательностью.

| Роль | Модель | Усилия |
|---|---|---|
| оркестратор | Opus | повышенный на планировании |
| `env-dev`, `ingest-dev`, `fetch-dev`, `analysis-dev`, `mcp-dev` | Sonnet | обычный |
| `render-dev` | Opus (в паспорте «сильная») — ждет решения: в указании Романа рендер перечислен среди Sonnet | обычный |
| `verifier` | Opus | повышенный на К1 и К2 |

Учет: в вечернем докладе — строка «запусков по моделям». До этого решения: Sonnet — 3 запуска (`ingest-dev`, `fetch-dev`, `analysis-dev`), Opus — 1 запуск `render-dev` и 2 продолжения; уровень усилий не задавался (по умолчанию).

## К-025. Рендер: подложка и overlay, подписи расставляет картограф

11.10.2026. Развитие К-018 по контракту overlay 1.0.0. Один проход по описанию карты — два выхода: `<карта>.png` (роли уровня `basemap` со своими подписями, без линейки, севера и легенды) с `provenance.json` только о подложке; `<карта>.overlay.json` (проверка по схеме контракта при каждой сборке). Превью (`--preview`, Pillow, цвета из токенов) — только для проверки. Отдельная легенда-картинка не выпускается — ждет решения Романа (вопрос в докладе 2: легенда строками в overlay вместо SVG). Подписи объектов расставляет картограф: правило по стилю роли, без наездов на другие подписи, знаки, границу территории, линейку, легенду, край места и подписи подложки (рамки берутся из движка подписей QGIS); не встала — выноска `leader_to`; не встала и так — в лог. Статус подложки — самый слабый у ее слоев; `reference` — ошибка до `image` 1.1.0 (образцы К1 собраны с пробной копией схемы и в альбом не идут).
