## Решения (предложения в DECISIONS.md)

Предлагаю записать как К-0xx «fetch: правила раскладки внешних источников»:

1. **Море есть как полигон, вычитание не нужно.** В `base/water` Overture классы `sea`, `bay`, `ocean` покрывают охват без суши: охват минус суша `base/land` равен морю с точностью 1e-16 (проверено на полигоне). Эти три класса кладутся в `water_class = sea`; они в источнике лежат друг на друге, поэтому от крупных отнимаются мелкие (непересекающиеся полигоны). Для прямого OSM море строится из `natural=coastline` (суша слева, вода справа, грани охвата справа от линии) — проверено только на синтетике.
2. **Кварталы:** суша охвата минус полосы улиц по классу (14 м express и main, 11 district, 8 local, 5 pedestrian от оси), без service и path, без подземных участков. Это то же, что полигонизация осей и вычитание полос, без лишнего шага. Отбрасываются части меньше 400 м2, больше 150 га и подходящие к границе охвата ближе 10 м (обрезаны охватом). Все числа — в `rules/fetch.yaml`, `blocks`.
3. **`object_id` улиц — по элементу OSM, не по сегменту Overture.** Сегмент Overture собран из нескольких элементов OSM (`sources[].between`) и режется на сегментах; сегмент режется обратно по элементам и тоннелям, участки одного элемента сливаются: `roads:osm-w123`, подземный участок `roads:osm-w123-t`. Без OSM-источника — `ovt-<GERS>`.
4. **Классы:** `track` → `service`; `unknown` → `service`; `crosswalk`, `sidewalk` (Overture-класс `footway`) → `path`; ссылки (`*_link`) наследуют класс основной дороги. Класс Overture вне таблицы — ошибка.
5. **Подписи и лицензии — по поставщику первой записи `sources`:** OSM → «OpenStreetMap через Overture Maps <выпуск>», ODbL 1.0; Microsoft ML Buildings → «Microsoft ML Buildings через Overture Maps <выпуск>», ODbL 1.0; Places → «Overture Maps Places <выпуск>», CDLA-Permissive-2.0 (для всех записей, как условия Overture).
6. **Places:** уверенность < 0,5 и закрытые заведения не берутся; точка Places внутри площадного объекта `land_use` той же группы — дубль, остается объект `land_use` (с названием и номером OSM).
7. **Сверка:** запись сведена — `object_id` по реестру (`poi_education:busgov-10`), геометрия из OSM, имя и вместимость из реестра, `confirmed_by = [ключ OSM, ключ реестра]`, подпись и лицензия через «; », дата — более поздняя; статус остается `reference`. Объект OSM из группы, которую покрывает загруженный реестр, без пары — «— не подтверждено реестром» в подписи. Запись реестра без координат и без пары в геопакет не попадает (отчет `fetch-<base>.reconcile.yaml`). Совпадение: тот же `poi_type`, расстояние не больше 150 м и общие различающие слова названия не меньше 0,6 (родовые слова и формы — в `rules/fetch.yaml`, цифры должны совпадать); без координат — единственное совпадение по названию.
8. **Реестры кладутся в кеш вручную** (`--file`, `--date`): порталы закрыты из облака, формат выгрузок не проверен; имена столбцов — данные в `rules/registries.yaml`, а не код.
9. **НСПД не подключается:** нет документированного открытого интерфейса, хост закрыт, массовая выгрузка по правилам портала, судя по всему, не разрешена; ЕГРН идет выписками и КПТ через `ingest`.
